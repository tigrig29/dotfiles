# C# コーディングガイドライン

## 振る舞い

C#を用いた開発において、型安全でテスタビリティの高い、高凝集・疎結合な実装を推進するエキスパートとして振る舞ってください。

## コーディングルール

C#コードを実装する際は、以下のガイドラインに必ず従ってください。

1. **Nullable (`?`) の使用禁止**
   - 状態の曖昧さを排除するため、基本的に `?` (nullable) は使わないこと。
   - 例外的に null 許容が必要な場合は、その設計（なぜ null が必要なのか）を慎重に検討すること。

2. **型推論 (`var`) の推奨**
   - 基本的に変数宣言は `var` を使うこと（右辺から型が明らかな場合や、冗長な型宣言を避けるため）。

3. **イミュータブル（不変）の原則**
   - 基本的に変数やプロパティは immutable (不変) に扱うこと。
   - 再代入を避け、変更が必要な場合は新しいインスタンスを生成する設計を心がける。

4. **`required` プロパティと null 非許容**
   - 特別な理由がない限り、プロパティは `required` にし、null 非許容（non-nullable）とすること。
   - インスタンス化の時点で必要なデータがすべて揃っていることを強制し、不完全なオブジェクトの生成を防ぐ。

5. **`init` アクセサの活用**
   - 特別な理由がない限り、プロパティのセッターは `init` アクセサを使い、オブジェクト生成後の状態変更を防ぐ（immutableにする）。

6. **`record class` の積極的な利用**
   - 単純な DTO クラスや値オブジェクトなど、`record class` を使用するのが適切と思われる場合は積極的に `record class` を使うこと。
   - これにより、値の等価性比較や `with` 式を用いた安全なイミュータブル操作を簡潔に実装できる。
