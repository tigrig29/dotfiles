# Git Committer

このスキルは、Gitリポジトリにおけるコミット作業を自動化し、一貫性のあるコミットメッセージ（Conventional Commits準拠、日本語タイトル）を作成します。

## ワークフロー

1. **変更内容の把握**:
   - `git status` を実行して、未ステージングおよび未追跡のファイルを確認します。
   - `git diff`（必要に応じて `--cached`）を実行して、具体的な変更内容を把握します。

2. **コミット範囲の特定**:
   - **現在の会話履歴**（直近の修正提案、バグ報告、実行したコマンドなど）を参照し、今回の変更がどのタスク（論理的な単位）に属するかを判断します。
   - リポジトリ全体の変更のうち、今回のタスクに**直接関連するファイルのみ**を選択します。
   - 関連性が不明確なファイルがある場合や、複数のタスクが混在していると判断した場合は、`ask_user` でコミット範囲をユーザーに確認します。

3. **ステージング**:
   - ステップ2で特定したファイルのみを `git add` します。

4. **コミットメッセージの生成**:
   - [conventional-commits.md](references/conventional-commits.md) のガイドラインに従い、メッセージを生成します。
   - **Type**: 変更の本質（feat, fix, refactorなど）を英単語で指定。
   - **Title**: 日本語で簡潔に記述。
   - **Body**: （任意）変更の背景や影響を日本語で補足。

5. **コミットの実行**:
   - `git commit -m "<message>"` を実行します。

## 推論のガイドライン

- **関連性の判断**:
  - 実装コード、それに対応するテストコード、および関連するドキュメント（設計書やPBIなど）はセットとして扱います。
  - 同時に行われた無関係な「ついで」の修正（タイポ修正やフォーマット調整など）は、コミットメッセージで言及できない限り、別のコミットに分けるか含めないようにします。
- **慎重な選択**:
  - `git add .` を安易に使用せず、個別のファイルを指定して `git add` します。

## 使用例

### 例1: 機能追加のコミット
- 会話: 「手動時間調整機能のロジックを追加して、テストも通しました」
- アクション:
  1. `Nipopo/Services/TimeAdjustmentService.cs` と `Nipopo.Tests/TimeAdjustmentServiceTests.cs` を `git add`。
  2. `feat: 手動時間調整機能のロジックを実装` というメッセージでコミット。

### 例2: 複数の変更がある場合
- 状況: 機能追加の途中で、既存の無関係なバグも直した。
- アクション:
  1. 会話コンテキストから、現在は機能追加に集中していることを確認。
  2. バグ修正ファイルは除外し、機能追加に関連するファイルのみをコミット。
  3. 「バグ修正も含めますか？」とユーザーに確認する。
