# Conventional Commits

コミットメッセージは、以下の構造を持つ必要があります。

```
<type>: <description>

[optional body]
```

## Types

- **feat**: 新機能の追加
- **fix**: バグ修正
- **docs**: ドキュメントのみの変更
- **style**: コードの意味に影響を与えない変更（ホワイトスペース、フォーマット、セミコロンの欠落など）
- **refactor**: バグ修正も機能追加も行わないコードの変更
- **perf**: パフォーマンスを向上させるコードの変更
- **test**: 不足しているテストの追加や既存のテストの修正
- **build**: ビルドシステムや外部依存関係に影響を与える変更（スコープの例: gulp, broccoli, npm）
- **ci**: CIの設定ファイルやスクリプトの変更（スコープの例: Travis, Circle, BrowserStack, SauceLabs）
- **chore**: srcやテストファイルを修正しないその他の変更
- **revert**: 以前のコミットを元に戻す

## 日本語メッセージのガイドライン

- **<type>**: 英単語（小文字）を使用します。
- **<description>**: 日本語を使用します。
  - 命令形ではなく、何をしたかを簡潔に記述します（例: 「〜を追加」「〜を修正」）。
  - 文末に句読点（。）は不要です。
- **[body]**: （任意）変更の動機や、以前の動作との対比など、詳細な説明が必要な場合に日本語で記述します。

### 例
- `feat: 手動時間調整機能のロジックを実装`
- `fix: APIの認証エラーを修正`
- `docs: READMEに使用方法を追記`
