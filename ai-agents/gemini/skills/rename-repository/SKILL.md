# リポジトリ名変更スキル (Rename Repository)

## 概要

GitHubのリポジトリ名を変更する際に必要となる、以下の3つの主要な更新作業を支援・実行します。

1. GitHub上のリポジトリ設定の変更
2. ローカルのGit設定（リモートURL）およびディレクトリ名の更新
3. ソースコード・設定ファイル内に記載されている旧リポジトリ名の置換

## ワークフロー

### 1. 新しいリポジトリ名の確認とGitHub上の設定変更

* ユーザーに対して、**新しいリポジトリ名**（および必要であれば新しいアプリケーション名）を尋ねます。
* `gh repo rename <新しいリポジトリ名> -y` コマンドを実行して、GitHub上のリポジトリ名を変更します。

### 2. ローカルGit設定・ディレクトリの更新

GitHub上の設定変更が完了したら、以下のローカル設定を確認・更新します。

* **リモートURLの確認・更新**:
  `gh repo rename` コマンドにより自動でリモートの origin URL が更新されることが多いですが、念のため `git remote -v` で確認します。更新されていない場合は、シェルコマンドを実行して更新します。
  ```powershell
  git remote set-url origin https://github.com/<ユーザー名>/<新しいリポジトリ名>
  ```
  ※ コマンド実行前に、現在のリモートURL（`git remote -v`）を確認し、ユーザー名などを特定してください。

* **ローカルディレクトリ名の変更（任意）**:
  作業ディレクトリの名前も新リポジトリ名に合わせて変更することをユーザーに提案します。（実行中のプロセスのカレントディレクトリである場合、Agentからの直接変更はエラーになる可能性が高いため、ユーザー自身に手動でリネームしてもらうか、エディタを閉じてから変更するよう案内します）

### 3. プロジェクトファイル内の文字列置換

プロジェクト内のファイルにハードコードされている旧リポジトリ名（例：`package.json`, `README.md` 等）を新しい名称に置換します。

1. **検索**: `grep_search` 等を用いて、現在のディレクトリ内で「旧リポジトリ名」が含まれるファイルを検索します。
2. **置換**: `replace_file_content` または `multi_replace_file_content` ツールを使用して、該当箇所の文字列を新しいリポジトリ名に更新します。
   * **対象となりやすいファイルの例**:
     * `package.json` (`"name"`, `"repository"`, `"bugs"`, `"homepage"` など)
     * `package-lock.json`
     * `README.md` (見出し、バッジのURLなど)
     * `.github/workflows/` 内のYAMLファイル
   * アプリケーション名も変更する場合は、関連するフィールド（例：`appId`, `productName`など）も併せて変更します。
3. **依存関係の更新（Node.jsプロジェクトの場合など）**:
   `package.json` を更新した後、必要に応じて `npm install` などのコマンドを実行し、ロックファイル（`package-lock.json`）を整合性のある状態に更新します。

## ベストプラクティスと注意点

* **事前の検索と確認**: 置換を行う前に必ず全体を検索し、どのファイルが変更されるかをユーザーに提示して承認を得てください。
* **文字化け対策 (Windows環境)**: ファイルの読み書きやコマンド実行においては、文字化けを防ぐために必要に応じて `-Encoding utf8` オプション（PowerShellの場合）を使用するか、ツールの標準機能を活用してUTF-8で正しく処理されるようにしてください。
* **自動コミットの確認**: 変更が完了した後、一連の変更をコミットするかどうかをユーザーに尋ね、「git-commit」スキルなどと連携してコミットを完了させるのが望ましいです。
